## 1. V2EX · 分享创造

**标题**：做了个浏览器点对点传文件的小工具，报 6 位码就能连

**正文**：

```
平时给同事传个几百 MB 的素材，流程总是：传网盘 → 等上传 → 发链接 → 对方下。中间这一跳很烦。

所以写了个小工具：两边打开网页，一方把 6 位取件码报给另一方，两个浏览器用 WebRTC DataChannel 直连，文件从一台设备直接流到另一台，不经过服务器。

几个实现上的选择：
- 不做 TURN：打不通就明确失败并给诊断（候选类型、失败原因），把「改用中转」做成显式按钮（R2，24 小时自动删）
- 同一个 Wi-Fi 下会走局域网直连，不占上行；跨网络靠 STUN 打洞
- 两端会显示 8 位校验码（DTLS 指纹哈希），对一下就知道没有中间人
- 后端只有信令：Cloudflare Worker + 每房间一个 Durable Object

地址：https://sixdrop.dev （不用注册、不用装）
代码：https://github.com/tryhtryr/sixdrop

已知限制：对称 NAT / 公司网可能打不通；Firefox/Safari 没有流式写盘，大文件建议用 Chrome/Edge；没有断点续传。

想听两类反馈：1) 你们那边打洞成功率高不高；2) 还有哪些场景值得做。
```

## 3. 少数派 Matrix

**标题**：不用网盘、不装 App：用 WebRTC 在两个浏览器之间直接传文件

**结构**（1500–2000 字）：

1. 起因：一次 2.3 GB 的录屏传输
2. 为什么选 WebRTC DataChannel（对比网盘/聊天工具/数据线）
3. 怎么用：同 Wi-Fi 自动发现 / 跨网络 6 位码
4. 技术上的三个取舍
   - 6 位码而不是长链接（微信里点陌生链接的心理成本）
   - 不做 TURN（成本 + 隐私预期）
   - 失败必须可见（候选统计 + 三条后续）
5. 实测：局域网 4.4 MB / 2 秒级；跨网络要看 NAT
6. 局限：对称 NAT、Firefox/Safari 内存、无断点续传、1 对 1
7. 适合谁 / 不适合谁

> 配图建议：大厅、房间两个标签、失败页诊断、校验码。

## 4. 知乎回答模板

找这些类型的问题回答（不要自问自答）：

- 「电脑传文件到手机，有什么不装软件的方法？」
- 「局域网内传大文件，什么方案最快？」
- 「微信传视频为什么会被压缩？怎么传原视频？」

**回答结构**（先解决问题，最后才提工具）：

```
先分情况：
1) 同一个 Wi-Fi：可以用局域网直连，根本不占宽带上行。浏览器里开一个网页就能做（WebRTC），两台设备互相发现后直接传。
2) 跨网络：看两边 NAT。锥形 NAT 能打洞，对称 NAT（公司网、校园网、部分 4G/5G）基本打不通，这时候要么换网络（手机热点），要么走中转。
3) 只是发个文档：聊天工具其实够用，别折腾。

我自己做的一个工具是 SixDrop（https://sixdrop.dev），思路就是 6 位取件码 + WebRTC 直连，不经过服务器。它解决的是「现在就要把文件给对方」这个场景，不适合长期保存和多人下载。
```

## 不要做

- 买「快速收录 / 秒收录」（百度 2024 年已下线该工具，剩下的都是骗局）
- 批量买外链、论坛签名群发
- 同一天在十几个站发同一段文案（容易被判 spam）
- 在别人帖子下面硬贴链接（适得其反，被删还掉权重）
